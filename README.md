# HF 探索打卡

一个 HTML 文件，一条从注册到发布模型的路线，一套多台电脑共用的进度。

**线上直接用：https://logic77lhl.github.io/hf-quest/**

纯静态单页：无构建、无依赖、无后端、无统计脚本。进度默认存在浏览器本地；需要多设备时接一个私有 Gist（用你自己的 token，只存本机）。

---

## 这个项目解决什么问题

Hugging Face 的文档很全，但「从注册到发布自己的模型」这条路径是散的。常见状态是：

- 收藏了一堆链接，不知道下一步该做什么
- 看了很多，手上没有产出
- 学两天就断了，也说不清自己走到哪

所以这个页面只做三件事：

1. **把路径拆成 42 个可验证的动作** —— 每课都写清「做什么 + 怎么算做完」，不是「读一下文档」。
2. **让坚持可见** —— 连续打卡、12 周热力图、XP、18 枚徽章。
3. **让进度跟着人走** —— 换电脑不用重新开始。

它是**路线图 + 进度账本**，不是课程本身。课程内容在官方文档，每课旁边就是链接。

## 适合谁

- 用过一两次 Hugging Face，但没系统走完一遍
- 想要「今天做什么」，而不是又一份资料合集
- 每天能拿出 20–40 分钟

不太适合：完全没写过 Python 的人（L1 开始要跑代码）；想找视频课的人（这里只有路线和链接）。

## 30 秒开始

1. 打开 https://logic77lhl.github.io/hf-quest/
2. 「今日打卡」点一下，连续天数开始计
3. 「学习路径」从 L0 第一课开始勾，右侧是官方文档
4. 需要跨设备时，再看「云同步」

不用注册、不用安装。想离线用：把页面另存为 `index.html` 双击打开即可（同步功能需要联网）。

## 里面有什么

| 阶段 | 主题 | 课数 | 学完能做到 |
|---|---|---|---|
| L0 | 起步 · 认路 | 6 | 说清 Hub 的六个入口，判断一个模型能不能商用 |
| L1 | 本地跑通 · 第一次推理 | 8 | 在自己机器上跑出 pipeline 输出 |
| L2 | 数据与词表 | 6 | 看懂 tokenizer，处理大数据集不爆盘 |
| L3 | 训练与微调 | 7 | 跑通 Trainer / LoRA / QLoRA / DPO |
| L4 | 推理与部署 | 7 | 量化、起服务、部署 Space、估算成本 |
| L5 | 生产与贡献 | 8 | 上传模型、写 model card、提 PR |

合计 **42 课**。另外还有：

- **12 个探索任务**：偏「输出」而不是「阅读」，比如对比 3 个中文小模型、复现一篇 Daily Paper
- **12 个微行动**：5 分钟能做完的小事，给不想开工的日子
- **18 枚徽章**：连续 3 / 7 / 21 / 60 天、每个阶段通关、42 课通关、笔记数、XP
- **12 周热力图**：每天的动作次数，颜色越深越多
- **实时榜单**：拉 Hugging Face trending 前 20，失败时用内置快照

XP 规则：课程 +10，探索任务 +25，完成一个阶段 +50，每天打卡 +5。

## 跨设备同步（每台电脑做一次）

> 为什么需要这一步：页面是纯静态的，`localStorage` 不会跨设备。这里用**私有 Gist** 当云存档，不需要服务器。

### 三步

1. **造 token**
   GitHub → Settings → Developer settings → Personal access tokens
   - classic：只勾 `gist`
   - 或 fine-grained：只给 **Gists: Read and write**
   - 建议设 90 天过期
2. **建存档**
   页面「云同步」→ 粘贴 token → 保存 → 点「创建新存档」，Gist ID 会自动填好。
3. **第二台电脑**
   打开同一网址 → 粘贴**同一个 token + 同一个 Gist ID** → 点「立即双向同步」。

接通之后：打开页面自动拉一次，改动后 4 秒自动推。头部只有一个状态胶囊：

| 状态 | 含义 |
|---|---|
| ✅ 已同步 | 干净 |
| ⏳ 待同步 | 本地有改动，等待上传 |
| ⚠️ 有冲突待裁决 | 停手，等你决定 |
| ⛔ 同步失败 | 面板里会写明原因 |

### 怎么合并

| 数据 | 规则 |
|---|---|
| 课程勾选、笔记 | 按最后修改时间取胜（所以取消勾选也能同步） |
| 打卡日期 | 取并集 |
| 每天动作数 | 取较大值 |

有两种情况**不会自动写入**，一定先弹预览：

- 两边都在上次同步后改过同一条 → 逐条选「用本地 / 用云端」
- 云端会取消你本地的完成项 → 列出具体课程名，确认后才动

原则：自动同步只做安全的事；会让本地丢东西的合并，必须由人决定。

### 写坏了怎么退

「云同步」→ 历史版本 → 列最近 12 个版本 → 选一版恢复。

恢复是**非破坏性**的：把那一版原样写成一个新版本，不删历史。

## 数据与隐私

| 存什么 | 位置 |
|---|---|
| 进度、笔记、打卡 | `localStorage["hf-quest-v1"]` |
| token、Gist ID、同步状态 | `localStorage["hf-sync-v1"]` |

- **token 不会进仓库，也不会进导出文件**。导出只含进度，不含凭证。
- 但 token 在本机浏览器里是**明文**。公用电脑别保存，用完点「清除」。
- Gist 是私有的；内容是明文 JSON（GitHub 不提供加密）。
- 仓库里没有任何 token、密钥或统计脚本。页面也没有第三方脚本，用户输入渲染时统一转义。

## 已知限制

- **同步不是原子写**。GitHub Gist API 不支持条件写入（`If-Match` 会返回 400），写前复查和真正写入之间有毫秒级窗口。极端情况下可能覆盖一次；但每个版本都带 `parent`，Gist 保留完整历史，可以查出来并回滚——是「可发现、可恢复」，不是「不会发生」。
- 同步依赖 `api.github.com`，需要能访问 GitHub API。
- 默认走 `hf-mirror.com` 镜像（国内直连 huggingface.co 常超时）。镜像可能比官方滞后，可在「进度与徽章」里切回官方。
- 实时榜单依赖镜像的 CORS；失败会自动回落到 2026-10-28 的快照。
- 不是 PWA，没有 Service Worker。离线使用需要手动保存 HTML。
- 数据是明文 JSON，不要往里放敏感信息。

## 自己部署一份

1. Fork 或新建仓库，把 `index.html` 放到根目录
2. Settings → Pages → Source 选 `main` / `/ (root)`
3. 等一分钟，访问 `https://<用户名>.github.io/<仓库名>/`

同步是可选的，不接 Gist 也能单机用。
